# 部署：晒图种草（reviews）

用户在已完成订单晒图（图片+文字+评分），先审后发，首页种草入口 + 晒图广场展示。

## 1. 新建 reviews 集合

云开发后台 → 数据库 → 新建集合 **reviews**
- 权限：**所有用户可读，仅创建者及管理员可写**
  （广场要展示别人的晒图 → 需所有人可读；写入只走云函数）

## 2. 部署 / 重新部署云函数

工具里右键 → 上传并部署：云端安装依赖
- **submit-review**（新）— 建议执行超时改 20 秒（含图片/内容安全检测）
- **admin-orders**（重新部署）— 新增了 list-reviews / review-status 两个 action

## 3. 内容安全接口（重要）

晒图是 UGC，文字会过微信 `security.msgSecCheck` 检测。
- 一般小程序注册后默认有「内容安全」接口权限，云函数 `cloud.openapi.security.msgSecCheck` 可直接调。
- 若云函数日志报权限错（如 -501007 / 接口未授权），去 mp.weixin.qq.com → 开发管理 → 接口设置，确认内容安全相关接口已开通。
- 代码策略：检测服务异常时**不拦截**，统一交人工审核兜底（先审后发），所以即使接口暂时不可用也不会卡住提交，只是少了机器初筛。
- 图片暂不做机器检测，靠 admin 人工看图审核（先审后发已是强保障）；以后要加可上 `mediaCheckAsync`。

## 4. 云存储

晒图图片上传到云开发存储 `reviews/` 路径（小程序端 wx.cloud.uploadFile）。云开发默认存储桶即可，无需额外配置。

## 5. 验证流程

1. 小程序：把某个订单状态改成「已完成」（admin 申请管理里改）
2. 进「我的订单 → 该订单详情」→ 出现「晒图种草」按钮
3. 点进去 → 选图（最多9张）+ 评分 + 文案 → 发布 → 提示「审核通过后展示」
4. 云开发 reviews 集合应多一条 status=pending 记录，images 是 cloud:// fileID
5. admin.html → **晒图审核** tab（默认「待审核」）→ 看到这条，图片正常显示（云函数转了临时 https）
6. 点「通过」→ 状态变 approved
7. 小程序首页下方「大家的晒图」横向条 + 进「大家的晒图」广场页 → 出现这条晒图
8. 同一订单再次进详情 → 晒图按钮变成「✓ 你已晒图」（一单一次）

## 已知 / 后续

- 图片机器检测（mediaCheckAsync）未做，靠人工审核
- 晒图暂只能从「已完成订单」发起（一单一次）
- 广场/首页只展示 approved；pending/rejected 不展示
- 提审小程序时：UGC 需在审核备注里说明「用户晒图，先审后发 + 内容安全检测」，并确保有内容管理机制（admin 审核）
